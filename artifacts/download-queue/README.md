# 下载队列第一批交付

批量粘贴多行链接，逐项解析并去重；播放列表展开为单项。单个视频与原有播放列表下载共用新的 Pinia 队列。最多保存 500 条任务，保留来源、标题、目录、格式、Cookie 文件路径、任务状态与成功输出路径；重启后的活动项标记为中断，由用户手动继续。

支持单项取消、单项失败重试、用当前 Cookie 设置重新解析、修改目录与格式、筛选和移除完成记录。取消正在解析的项会等待解析返回并丢弃结果。队列暂停会完成当前项后停止。删除队列记录不会删除下载文件。

每次下载与重试使用独立 requestId，前后端和全局活动条过滤迟到的旧进度。取消 IPC 返回前不启动下一项。下载 IPC 直接返回取消状态与最终文件路径，完成记录不依赖终态事件及时送达。

验证包括 20 个链接中部分解析失败、等待项及活动项取消、迟到取消命令、单项格式与目录修改、成功项不重复、重载恢复、解析取消、Cookie 设置刷新、损坏存储保护与写入失败暂停。浏览器覆盖 720、800、900、1180px，使用独立 Chrome 和模拟 Tauri IPC；截图见本目录。

Rust 40 项检查通过，含真实 yt-dlp 的本地媒体下载、失效媒体地址恢复、取消、输出路径与进度消息序列化。EXE / MSI 最终打包完成，哈希和相称验证记录见 validation.json。

真实网站的账号下载、Windows 安装升级与 WebView2 窗口仍未实测。恢复队列不保证每个媒体来源都支持部分文件续传。变更仍在本地，未提交、推送或部署。
